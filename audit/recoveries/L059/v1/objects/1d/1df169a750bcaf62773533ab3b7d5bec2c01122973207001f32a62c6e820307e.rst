Public replay of the L059 cubic graph inputs
===========================================

This is a transport adapter for the independently reviewed L059 principal
packet, edition 2. It introduces no mathematical result and does not repeat
the subgroup census. The original ``verify_cubic_sources.py`` is preserved
unchanged in that packet.

The two numeric inputs contain precisely the 796 symmetric cubic records of
order at most 2048, the 43 semisymmetric cubic records of order at most 768,
and the 261 explicit permutations identifying reused earlier inputs. The
roster is extracted from the exact Conder--Potocnik census files acquired by
the original verifier. Its two non-LCF entries use the already reviewed
Petersen and Coxeter constructions. The latter construction retains its
attribution to Sage's CoxeterGraph source. Full upstream files remain
hash-only entries in the source ledger.

The public replay needs only pynauty, this directory's three JSON input
files, and the following byte-identical derived inputs, under ``--derived``:

* ``cubic_2048_bipartite.json``;
* ``cubic_2048_nonbipartite.json``;
* ``cubic_markings/inputs.json``.

Each may instead be stored as the same pathname followed by ``.gz``. The
checker hashes its decompressed bytes against the acquired provenance. It
does not read any full article, webpage, source roster or Sage source file.

Run ``python replay_numeric_inputs.py --derived PATH --output NEW.json``.
This reconstructs each graph, checks exact retained edges, cubic degree,
connectedness, bipartition, pairwise nonisomorphism, and all 261 actual vertex
maps. The output is refused if it already exists. Optimized Python is
rejected. Classification completeness remains the same explicitly borrowed
primary census premise as in the reviewed manuscript.

``extract_numeric_inputs.py`` is an acquisition utility, not a runtime
dependency of this public replay. It records the full primary-file hashes,
line numbers and exact numeric line hashes, checks the original complete
roster lengths before applying the two cutoffs, and pins the previously
reviewed reuse report. No runtime rewriting or patching of the old verifier
is performed.
