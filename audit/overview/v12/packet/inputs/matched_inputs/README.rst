Symmetric executable-listing exclusions: proposed inputs
=======================================================

This is an input proposal, not acceptance of new compression factors. It
covers the complete Chamber, ChiralEnumeration and Operations boundaries:
six originals and eleven replacement manuscripts, 17 PDFs and 215 pages.
Only seven concrete executable blocks in L008, L028 and N006 are excluded.
The eleven replacement papers have explicit empty listing masks. Scientific
contracts, required computations, data, common papers and companions remain
unchanged. The other fourteen PDF documents retain exact previous counts and
text hashes. Source mathematical algorithms and their proofs are not removed.

``precount_policy_manifest.json`` pins the policy and twelve page-local mask
chunks before the first new count. It is not overwritten by the final author
manifest. The masks include literal program comments, retain their whitespace
as separators and never include page headers or footers. Thus every old
raw/selected furniture convention remains unchanged. The full glyph maps are
applied at their original offsets before listing exclusion. No glyph, font
rule, diagram proxy, dehyphenation rule or scientific edition has changed.

The primary remains NFC nonspace characters in calibrated selected text,
now with executable blocks excluded on both sides. All thirty standard
coordinates remain available for all seventeen documents. Operations also
retains all ten text-only graphical-proxy sensitivity coordinates per document.
The resulting 510+90 count cells are inputs only. Unextracted graphics,
external proof costs and complete historical software costs remain unknown.

In the primary coordinate, source costs change from 21,784 to 20,159 for
L008, 29,599 to 27,594 for L028, and 56,001 to 55,740 for N006. These are
text lengths, not ratios. The seven block masks do not remove Lemma 4.5 or
its proof from L028's Section 4.2, the theorem/proof preceding L008's Section
5, or the McL construction argument surrounding N006's pseudocode.

Whole software
--------------

``software_inventory.json`` preserves the inherited semantic inventories.
``unchanged_software.json`` adds exact current routes to all 46 whole files:
Chamber's two programs, three drivers and three partial formal files;
ChiralEnumeration's three programs, one driver and one formal file; and
Operations' 23 programs, two required decoders, five operational drivers and
three partial formal files. No code routine or witness data has been pruned.
Operations' complete external representation/installed-file inventory also
remains bound. Large external data are not reloaded merely to change a text
mask. The complete partial appendices are still alternatives only; there is
no newly invented full Operations printed-code route.

Old inventory wording is historical evidence, not current policy: optional
validation is not a conditional proof premise. Actual required programs,
decoders, data and retained theorems remain required. Source listings are
retained in their unchanged source PDFs and this exact mask inventory, not
deleted from the scientific record. No software-inclusive factor is permitted
without symmetric source and replacement software inventories.

Replay and review scope
-----------------------

Use Python with pypdf 6.13.0::

  python3 -B -O check.py --public-root /path/to/math_compression \
    --sources-root /path/to/leemans --out /fresh/directory

The checker re-extracts the exact seventeen PDFs, verifies every original
page/extraction/glyph-context binding and all 600 accepted prior coordinate
cells, then applies only the declared masks. It verifies the 46 unchanged
whole-file bindings and rejects ten meaningful boundary mutations. No source
text, raster, GAP output or compiler object is exported. No GAP/Lean proof
or embedded-font outline parser is rerun: the distinct accepted old actual
font/dictionary/byte audit is reused on identical PDF bytes. This author
input replay is not an independent input acceptance. Root must independently
review the masks and recount before any new factors are calculated.

``visual_review.json`` binds fresh viewing of the eight listing pages and
explains unchanged-page reuse. The concise reader adds no scientific claims.
The accepted listing-policy review is separately bound; earlier input
packets, scientific editions and the current public tree remain unchanged.
