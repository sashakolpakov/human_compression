First broad L100 traversal: separate operational caller design
============================================================

This is a private operational interface, not a target receipt or root acceptance.
The scientific predecessor is exhaustion_component_v2, manifest
01ab26a1194efdcbc980e358eb4da425d13eb5d30f5602b86827d27214d914ca.
Its exact distinct acceptance is exhaustion_review_v2, manifest
5ffd79c6177a1550a10c57edde2abae61769a024775180b176afa2c7b69d47e9,
and its exact root adoption is exhaustion_adoption_v2, manifest
1117e60a09345ab4060613c791b6e07c95f0581cf525486eed052c47c80a7c2d.
The caller requires these actual gates before creating any output. Root still
reviews this separate operational interface before its one target execution.

The first authorized request is one fixed traversal of Borel IDs 95 down to 1,
in the fixed saved named permutation model, with REQUIRE_2T=false and a single
60-second external target cap. The unchanged engine's per-Borel rank bound is
Omega([G:B])+1, with terminal emptiness required. A preparation-only control
may create the driver/input receipt but may not invoke RunBorel.

Required preflight
------------------

Verify the exact author manifest and every export, the exact accepted review
manifest and every export, and its exported binding to that exact author path
and hash. Recheck the complete method dependencies. Pin the actual GAP launcher
and retained runtime premise, caller, preparer, generated driver, fixed
input_catalogue01.g, catalogue_loader_v2.g and legacy_functions.g. These last
four are the actual mathematical inputs Read by the target. The complete
367-inclusion input is already acquired, not regenerated with a new random
model map. The final driver must be byte-identical to the frozen preparer's
output for this exact output path and the literal 95..1 request.

Execution and receipt
---------------------

Write an ACTIVE owner record before spawning the process. The receipt must
explicitly say target_census=true; the earlier run_bounded.py's false value is
only for bounded small controls and must not be reused. Preserve stdout,
stderr, the exact command and deadline, actual return/timeout state and every
checkpoint, including incomplete files. Wait for the child terminal state.
No external timeout, nonzero return, nonempty stderr, GAP Error, changed input
or missing final marker can be called a completed whole request.

After the target stops, audit only done files whose exact unique BOREL_COMPLETE
marker occurs in stdout. A bounded read-only GAP audit should parse these
returned records in the exact same fixed model, verify each Borel ID/order,
nonnegative level counts, terminal empty level, rank bound, matching per-rank
checkpoint lengths and exact final geometry list. The audit also reconstructs
the accumulated full-ambient families from the recorded levels and checks every
panel is an actual overgroup in the fixed ambient group. Its twenty-second cap
is separate from the sixty-second search cap. It must not call RunBorel or
resume any anchor. For a genuine deadline, verified earlier done anchors can
be recorded separately, but the unfinished requested anchors remain explicit.
The whole request is complete only if the process returned cleanly, every one
of the 95 IDs is verified once, and the final requested-set marker exists.

Pin every returned file and the audit's inputs/outputs. Rehash every preflight
input after both target and audit. A receipt is invalidated if any changes.
The receipt must distinguish complete request, partial deadline, failed
execution, failed checkpoint audit and input mutation. It must expose all
unpaid anchor IDs and must not automatically launch a continuation.

Necessary bounded controls before any target
--------------------------------------------

Exercise the classifier with complete, deadline, failed exit, warning, missing
marker, duplicate/missing IDs, and input mutation. Exercise the actual checkpoint
reader only on the tiny accepted fixtures, including B=G/no-panel termination,
nonempty final level, wrong Borel order and a truncated checkpoint. Verify the
actual preparation-only command and literal generated driver. Deliberately
damaged author/review/namespace/binding gates must reject before an output is
created. All optimization guards precede filesystem changes.

Scope
-----

A completed run supplies a specified-group inner-conjugacy/type catalogue.
It does not supply full Aut(G) fusion, bare-incidence isomorphism classification,
the printed automorphism/correlation groups, all construction routes or whole
L100 recovery. Existing legacy two-transitivity finish/truncation filters are
not part of this design. The next census is materially new and has not run;
no completed anchor is to be repeated by a later continuation.

Operational authorship and controls
----------------------------------

publication_recovery wrote this caller, audit and controls. Root supplied the
fixed one-traversal scope, input-binding and returned-anchor requirements and
distinctly reviewed the underlying mathematical method. Peer advice, if any,
is recorded separately; it is not silently attributed as distinct acceptance.

controls.py passed 48 focused checks: transcript/status cases, literal changed
and missing inputs, namespace guards, actual small child return/deadline/launch
failure, all eight acquired S3 checkpoint files including the top Borel, eight
damaged checkpoint cases and one missing checkpoint, actual preparation-only
CLI, three exact gate rejections before output and four optimization guards.
The fixed target driver was prepared but never run. No search or mathematical
enumeration was repeated by these controls.

The preflight checks the actual GAP executable and libgap bytes and retains the
accepted GAP algorithms as a software premise. It does not claim a proof of the
runtime or an exhaustive trace of every package/library file loaded by GAP.
The explicit mathematical Read inputs and generated driver are all pinned.

An interrupted or externally killed wrapper leaves its ACTIVE record as an
unclosed attempt, never as completed evidence. The child controller kills and
waits on its own process group when it handles a deadline or keyboard interrupt.
No automatic retry or continuation is provided.
